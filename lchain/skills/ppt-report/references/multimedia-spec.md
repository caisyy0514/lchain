# PPT 图文、图表及文献 spec

以下示例展示可选的混排能力。实际报告按每页内容选择纯文字、图片、图表、表格或混排，不要求全部使用，也不设视觉内容比例。

以下数字/链接**仅为格式演示，不是临床证据**。实际报告替换为经过核验的真实资料，不直接复制示例文献。

```json
{
  "title": "指标变化与行动建议",
  "author": "报告团队",
  "references": [
    {
      "id": "report-1",
      "title": "用于演示的资料名称，实际应替换",
      "authors": ["资料作者"],
      "year": 2026,
      "source": "已核验的期刊或机构",
      "url": "https://example.org/replace-with-verified-source"
    }
  ],
  "slides": [
    {"type": "title", "title": "指标变化与行动建议", "subtitle": "格式演示；不作为诊疗证据"},
    {
      "type": "columns",
      "title": "所见与解释",
      "ratio": [1, 1],
      "left": [
        {"type": "text", "text": "此处说明图片中与结论相关的发现，并清楚区分事实与推断。", "citations": ["report-1"]}
      ],
      "right": [
        {
          "type": "image",
          "path": "/repo/attachments/images/verified-figure.png",
          "alt": "描述关键所见及其位置",
          "caption": "图 1：检查所见（填写检查日期）",
          "source": "原始报告或图片机构、日期",
          "citations": ["report-1"]
        }
      ]
    },
    {
      "type": "columns",
      "title": "变化与比较",
      "left": [{"type": "text", "text": "解释变化的范围、缺测原因和局限。不同时间点须具有可比性。"}],
      "right": [{
        "type": "chart",
        "chart_type": "line",
        "categories": ["基线", "第1周", "第2周"],
        "series": [{"name": "指标甲", "values": [8.2, null, 6.8]}],
        "unit": "mmol/L",
        "caption": "图 2：格式演示的合成数据",
        "source": "测试用合成数据，不作为临床证据",
        "alt": "缺测点不连接，数值在图下方列出"
      }]
    },
    {
      "type": "table",
      "title": "证据与局限",
      "headers": ["结论", "证据", "局限"],
      "rows": [["示例结论", "核验原始资料", "样本和适用人群须匹配"]],
      "caption": "表 1：证据对照",
      "citations": ["report-1"]
    }
  ]
}
```

## 内容块与兼容字段

- `text`（同义 `paragraph`）：`text` 字符串，支持 `**加粗**` 和 `*斜体*`。
- `image`：必填 `/repo` 下绝对 `path`；`caption` 写图号/解释，`source` 写可读来源，`alt` 描述图意。图片嵌入且等比完整显示。扫描长图先准备有上下文的局部放大图，勿依靠缩小原图。
- `table`：`headers` 字符串数组，`rows` 二维数组；每列含义和单位清楚。可选 `column_widths:[1,1,3]` 按相对权重分配列宽，长度必须等于列数；可选 `align:["left","right","left"]` 逐列设置对齐。未指定时等宽，纯数字/百分比列（可含“缺测”）自动右对齐；单位建议写在表头。换行、行高与分页均使用实际列宽。独立表格自动续页并重复表头；双栏内放不下会报错。最多 6 列；超过表头列数报错，缺少的尾部单元格显示为空。
- `chart`：下述统一数据接口。可在独立页或 `columns` 里使用。
- `columns`：`left`、`right` 各为非空块数组；`ratio` 默认 `[1,1]`，允许 `[2,1]`、`[1,2]` 或其间比例。每块可有小标题 `title`。文字/表格按内容占位，剩余空间分配给图片/图表，超量拒绝生成。可在任一侧组合多个块，不支持嵌套 columns。
- 旧 `two_column` 的 `left`、`right` 保持字符串/要点对象数组，不等同于 columns。
- 旧 `bullets` 保留字符串项及 `{text,level}` 项，level 仅 0/1；现在要点对象也接受 `citations`/`source`。超过 6 条或超过可用高度自动分页。单条长到放不进一页时要求先拆分。
- 任何页/块的 `caption`、`source`、`citations` 在正文可见；独立页的 `notes` 仍是可选讲稿。表格内若需逐行来源，可增设“来源”列；不要手工编造与文献目录不一致的序号。

## 内容完整性与标题页

普通内容页必须提供可见主体，不能以标题、备注、来源或文献条目充数。两种双栏中的每个内容块也需有实际内容；仅有小标题的空块应补齐或重新编排。保留每页应讲的信息，不通过改成 `section`、删页或写“待补充”占位句来掩盖遗漏。

| 页型 | 内容要求 |
| --- | --- |
| `title` / `section` | 明确的封面或章节过渡，提供非空 `title`，可选 `subtitle`。若还有正文，改用内容页型，不能写入会被忽略的正文字段。 |
| `text` / `paragraph` | 提供非空 `text`。 |
| `bullets` | 提供非空 `bullets` 数组，每项为有内容的字符串或含非空 `text` 的对象。缺省 type 仍按此页型处理。 |
| `table` | `rows` 至少有实际数据行，只有表头不算内容；数值 `0` 是有效数据。 |
| `columns` / `two_column` | 两侧均有相应类型的内容，逐块/逐要点核对；单栏内容可改为独立页型。 |
| `image` / `chart` | 有效图片或实际图表数据即可，不要求额外段落或混排。 |

正文字段按上表填写。`content`、`body`、`blocks` 或 Word/HTML 中的 `items` 不能替代 PPT 的 `text` / `bullets`；脚本报错时修正字段并保留其中原有内容，再重新生成。若资料确实未提供某项信息，只能说明经核对的具体材料缺口，不能猜测患者事实来填满页面。

```json
{
  "title": "报告结构示例",
  "slides": [
    {"type": "section", "title": "检查资料"},
    {
      "type": "bullets",
      "title": "本页的实际内容",
      "bullets": [
        "把已经核对的原始资料内容填写在这里；此字符串仅为字段演示。",
        "每个要点应支持本页主题，并按需要关联实际来源。"
      ]
    }
  ]
}
```

## 患者附件图片：原图与细节页

- 从当前患者附件选择与本页所见相关的原始截图/图片；若资料在 PDF 中，按需将相关页渲染为图片。需要让读者核对字段或定位所见时，嵌入真实图像，OCR 摘录或链接不能代替必要原图。`path` 必须指向实际存在的 `/repo` 下本地文件；不要把远程链接、文件名或设想中的路径当作已准备的图片。
- 保留原文件。格式转换、方向校正、PDF 页渲染、加定位标记或局部放大均保存为派生副本，并在 `source` 写清原附件名、适用的页码和已知检查/报告日期；未知日期省略或注明未提供，不编造。局部图还要标明原图图号及区域。仅做显示所需处理，不补写、擦除、生成式修复或重绘数值、单位、病灶等临床信息；定位框/字母不得遮住关键字段。
- 手机照片先检查 EXIF 方向。生成器按原始像素尺寸布局，不会自动按 EXIF 转正；应在派生副本中应用该方向，导出正常方向的 PNG/JPEG 展示文件，移除或重置已应用的方向标记，避免客户端再次旋转，原件仍保留。
- 截图细节优先使用独立 `image` 页的全宽区域；只有字段仍清晰时才与解释并排。长图或密集报告可用“完整上下文 + 标记区域局部放大”分成相邻页；标明局部图，避免把截取部分当作完整报告。多图按检查时间、原页序或讲解顺序稳定排列，沿用图号与区域字母。无须规定图数或像素配额，以最终演示尺寸能读出相关字段为准。
- `caption` 说明本图关注点和图号，`source` 追溯患者附件；外部科学解释通过 `citations` 连接已核验文献，两者不互相代替。图注与来源紧贴对应图片，和页底文献区保持间距；空间不足就拆页，不能缩掉关键细节或省略依据。原件本身模糊时说明无法辨认，不以放大或猜测制造清晰结果。

以下是可改写的两页截图 spec，仅用已有字段，不含临床结论或虚构文献。附件名、路径及区域 A 仅示范用法：先核对实际附件，在当前会话目录准备标记副本和对应局部副本后再填写。若来自 PDF，将 `source` 改为真实文件名及页码，例如“患者附件：检查报告.pdf，第 2 页（日期未提供）；区域 A 放大副本”。

```json
{
  "title": "患者资料所见",
  "slides": [
    {
      "type": "image",
      "title": "检查截图与关注区域",
      "path": "/repo/threads/current/images/report-context-a.png",
      "caption": "图 1a：原始截图上下文，关注区域标为 A",
      "source": "患者附件：检查报告截图.png（日期未提供）；仅添加区域 A 定位标记的副本",
      "alt": "完整检查截图，区域 A 对应下一页局部放大位置"
    },
    {
      "type": "image",
      "title": "区域 A：核对关键字段",
      "path": "/repo/threads/current/images/report-detail-a.png",
      "caption": "图 1b：图 1a 区域 A 的局部放大，保留相关字段名称、数值及单位",
      "source": "患者附件：检查报告截图.png（日期未提供）；区域 A 放大副本",
      "alt": "原始截图区域 A 的局部，供对照字段名称、数值和单位"
    }
  ]
}
```

## 图表规则

```json
{
  "type": "chart",
  "chart_type": "bar",
  "categories": ["A", "B", "C"],
  "series": [{"name": "指标", "values": [1.2, 2.5, null]}],
  "unit": "mg/L",
  "caption": "示例合成数据",
  "source": "格式演示，不作医学推断"
}
```

- `chart_type` 为 `bar` 或 `line`；1–8 个不重复类别（line 至少 2 个），1–4 个非重名系列，每个系列 `values` 与类别等长，且至少一个有效值。
- 数值只接受有限 JSON 数字（绝对值 ≤ 1e12）；拒绝字符串、布尔值、NaN/Infinity。`null` 是缺测，柱状图不画该柱，折线图不跨缺测连线，数据表显示“缺测”。
- `unit` 与 `source` 或 `citations` 必填。同图统一单位；无量纲写具体“比值”等，不能省略含义。
- 折线横轴按类别等距排列，不是连续日期轴。真实随访间隔不等时，按统一时间间隔补齐缺测类别，或嵌入带真实时间轴的科学图；不要把等距位置解释为等时长或据此推断变化速度。
- 轴自动包含零点，包括负值，以 1/2/2.5/5 × 10ⁿ 生成易读刻度；不接受 `y_min`/`y_max` 截轴。只对刻度取整，数值表保留输入值。只表示实际点估计，不生成未提供的置信区间、误差线或显著性标记。
- 图例放左上、单位放右上，类别下方是浅底原始数值区，每行显示系列名称。同系列的颜色、点形和线型在图例/图中一致，缺测显示灰色“缺测”。不把靠近的折线标签叠在一起。长类别/图例或太多系列使双栏区域不足时，移为独立页。
- 形状/线条/文本可编辑，不内嵌 Excel 图表数据工作簿；建议通过修改 spec 重生成以保持图形比例与原始数值一致。

## 参考文献规则

```json
{
  "references": [{
    "id": "stable-id",
    "title": "经原文核对的题名",
    "authors": ["作者甲", "作者乙"],
    "year": 2026,
    "source": "期刊、指南机构或原始资料来源",
    "doi": "10.1234/example",
    "url": "https://example.org/verified-publication"
  }]
}
```

- `id`、`title` 必填，`source`/`doi`/`url` 至少一项；`authors` 可为字符串数组或字符串。缺少已核验元数据时可省略，不杜撰作者、年份或 DOI。
- DOI 可写裸 DOI、`doi:` 前缀或 `https://doi.org/` 地址；URL 必须为 http(s)。示例 DOI 只展示结构，不可作为真实文献使用。
- 相同 DOI/URL 只出现一次，以首次定义决定编号，别名 `id` 仍可引用。同 id 不同定义、DOI 与 URL 指向不同已有条目、未知 citation 都会报错，先核对资料再重生成。
- `citations:["stable-id"]` 在相关文字/图注处显示上标编号，当前页底部列出对应文献；报告末尾仍追加完整“参考文献”页并自动续页。两处使用相同全局编号。不会自动搜索/补全未知文献，不会将脚本输入验证冒充文献真实性核验。
- 若只有用户原始检查资料，可把它列作资料来源并说明日期；不要伪造论文来增加“科学性”。如确无引用材料，可不传 references，并在报告中说明证据边界。

### 每页底部的文献区

按页文献自动启用，不需要手工排页脚或新增 spec 字段：

- 脚本收集该页 slide、各条要点、图文双栏子块及旧 `two_column` 要点的 `citations`，按全局编号去重。引用放在它实际支持的论断/图表上；只有支持整页的文献才放 slide 级。
- 同页多次引用同一来源，底部只列一次。自动拆分要点页后，每页只列其实际内容涉及的来源；slide 级引用会保留在对应的续页。表格续页保留整表的引用。
- 页底条目展示题名、出处、年份及可核对的位置：有 DOI 时优先显示 DOI，否则显示提供的 URL；文末保留提供的 DOI 和 URL。作者数组超过三人时缩为前三名加明确的“等”，字符串作者保持原样，文末保留完整信息。不要用无题名的编号串或“见文末”替代本页文献，也不要为了美观编造缺失元数据。
- 引文上标沿用青绿强调色，与正文/图注处于同一个文本块；普通文字中的 `[1]` 不会自动变成引文。无需用空格、单独文本框或手写序号定位标记。
- 文献区在页码上方使用细分隔线，与正文、图注保留间距。脚本先按真实换行测量文献高度，再分配正文区域；不会把文献叠加在图表上。内容与引用过多时拆页，不能隐藏来源、截掉题名或不断缩小字号。
- 无引用页不显示空文献区；文末完整参考文献页不再重复底部列表。`source` 仍用于图注/原始资料说明，不会自动变成未定义的公开文献。

## 学术版式选择

| 内容问题 | 推荐布局 | 写作与排版要点 |
| --- | --- | --- |
| 背景、论点或行动建议是什么 | `text` / `bullets` 文字页 | 用标题、段落或要点讲清即可；按论断需要引用文献。 |
| 当前主题或章节是什么 | `title` / `section` | 保持清晰标题与留白，无需为填满版面配图。 |
| 原图中看到了什么 | 独立 `image`，或说明 + 图片 `columns.ratio:[1,1.2]` | 患者截图优先全宽与细节页；并排时关键字段仍须可读。上下文与局部图位置对应，图注标明原附件。 |
| 数值变化意味着什么 | 图表 + 解释，`columns.ratio:[1.25,1]` | 解释写核心发现、局限和下一步；图表/数据来源置于图下。 |
| 多组或多时间点如何比较 | 独立 `chart` 页 | 优先给图表足够宽度；沿用系列名称和顺序，不跨页交换同系列颜色。 |
| 方案、证据或边界如何对应 | 独立 `table`，按内容设 `column_widths` | 说明列可宽于指标列；保留表头和必要单位，数字右对齐。 |

一页围绕一个问题，标题提供判断，正文解释依据。重要数字不必全部加粗；只强调结论、关键风险或行动。图注中的图号/说明加粗，来源维持次级色；图片与图注成组、表格来源紧跟表格，避免把来源独立放在远处。页底文献采用 13 pt 与悬挂编号，条目按实际长度换行。文末完整文献的编号单独对齐，正文 16 pt、DOI/URL 14 pt，续页保持相同布局。

不要为了整齐把正文缩小、裁掉图片、去掉单位或删减参考文献；内容过多时拆页。确认加粗、显式换行与自动换行同时出现的段落末行仍可见，并用真实渲染检查所有图例、数值行、图注和文献。
