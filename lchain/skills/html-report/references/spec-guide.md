# HTML 报告输入与排版

JSON 顶层包含 `title`、可选 `subtitle`/`author`/`meta`、`blocks` 数组及可选 `references` 数组。素材路径可以是绝对路径，或相对 spec 文件目录的本地路径。

`blocks` 可仅由标题、段落和列表组成；`image`、`chart`、`table`、`columns` 都是按需选项。以下混排示例说明可用结构，不代表每页或每章的视觉内容配额。

## 基础 blocks

| type | 字段 | 说明 |
| --- | --- | --- |
| heading | text、level（1–6） | 自动目录与唯一锚点；同名标题不会产生重复 id |
| paragraph / quote | text | 支持加粗、斜体、行内代码、安全链接及 `[@id]` |
| bullets / numbered | items 字符串数组 | 列表末尾可附整组来源/引用；单项可内嵌 `[@id]` |
| table | headers、rows、caption | rows 每行长度必须一致；headers 可省略但不能是零列表格 |
| image | path、alt、caption、source | PNG/JPEG/GIF/WebP/自包含 SVG；按比例显示，不裁切 |
| code | text、lang | 转义代码；不执行脚本 |
| page_break | 无 | 仅影响打印分页 |

所有 block 可提供 `citations: ["reference-id"]` 与 `source`。图片、表格和图表的 `caption` 显示为图注/表注；图片和图表的 `alt` 用于无障碍描述。图片必须来自已存在的本地文件，单图不超过 30 MiB；不支持的格式须先转换为 PNG。SVG 禁止脚本、嵌套远程图片、外部字体/样式等资源。不使用远程图片 URL，也不以“图片缺失”占位成功交付。

为新图片提供描述内容而非文件名的 alt，并写清图注和来源。生成器对旧 spec 仍允许只提供 path，回退以 caption/文件名作为 alt；这只是兼容旧内容，不是新报告推荐格式。

## 患者截图与图片

从本次患者附件取用与解释有关的截图、检查单照片或图片，使用真实存在的本地 `path`。只有解析文字时应先查找对应原图；来源为 PDF 时，可将相关页渲染为图片，并记录原文件和页码。无法取得必要图片时说明缺失，不能重绘一张看似原件的检查单。

先核对阅读方向；携带 EXIF 方向的照片宜在派生副本中将方向落实到像素，避免浏览器与打印方向不一致，不镜像医学图片。HEIC 等不支持格式先转换为 PNG/JPEG；不能靠修改后缀转换。原图保留，副本的图注/来源说明“格式转换”“局部放大”或“标注”，不修改原有数值、文字、颜色或诊断区域。标记线框放在副本中并避开关键信息。

下面示例使用两个已准备的图片文件，仅说明字段。实际应替换附件名称、位置与图片路径；短截图可只保留一张全宽图，无需生成局部图：

```json
{
  "title": "检查资料与说明",
  "blocks": [
    {"type": "paragraph", "text": "结合图 1 的原始上下文，解释图 2 所示结果；具体结论与数值应核对本次附件。"},
    {
      "type": "image",
      "path": "/repo/threads/current/images/report-overview.png",
      "alt": "患者提供的检查资料概览，框 A 对应下方局部结果区",
      "caption": "图 1 检查资料概览（框 A 为图 2 的位置）",
      "source": "患者提供：检查资料.pdf，第 2 页；渲染副本，添加位置框 A"
    },
    {
      "type": "image",
      "path": "/repo/threads/current/images/report-detail-a.png",
      "alt": "原图框 A 的局部结果区，保留项目、结果、单位及参考范围",
      "caption": "图 2 结果区局部放大（对应图 1 框 A）",
      "source": "同一附件第 2 页；从未标注的渲染副本提取局部，未改动检查内容"
    }
  ]
}
```

`caption`、`source`、`alt` 均不会自动裁图、旋转或添加位置框；先用可用图像工具生成对应副本，再填写与实际处理一致的说明。多个附件按检查时间或解释顺序编号，正文用图号关联。图片嵌入 HTML，分享时无需访问原附件路径；仅有图片来源不要求新增论文引用。

## 双列图文与图表混排

```json
{
  "type": "columns",
  "ratio": [1, 1.2],
  "left": [
    {"type": "paragraph", "text": "围绕图中关键发现解释结论。", "citations": ["evidence-1"]}
  ],
  "right": [
    {"type": "image", "path": "../images/finding.png", "alt": "关键发现位置", "caption": "图 1 检查资料", "source": "本次原始检查资料"}
  ]
}
```

left/right 均可放多个 blocks，包括 chart 或 table。ratio 是两个 0.2–5 的有限正数，代表相对比例；两列最多嵌套两层。桌面双列、宽度不超过 700px 时按左→右单列阅读，打印为单列。避免把很长的正文与很短的图片硬放一行；把图及解释作为一个内容单元。

## 数据图表

```json
{
  "type": "chart",
  "chart_type": "line",
  "categories": ["基线", "第1周", "第2周", "第3周"],
  "series": [{"name": "演示指标", "values": [8.1, 7.2, null, 6.3]}],
  "unit": "mmol/L",
  "caption": "图 2 指标趋势（演示数据）",
  "alt": "第2周缺测，曲线在此断开",
  "source": "合成演示数据，不构成临床证据",
  "citations": ["evidence-1"]
}
```

- `chart_type` 只支持 `bar`（默认）和 `line`；柱图包含零基线，折线不跨 null 连接。
- `categories` 为 1–12 个互不重复的字符串，折线至少 2 类；类别名最多 36 字符，且必须能在本图 4 行标签内读完。超出时缩短标签或拆图，不截断标签。
- `series` 为 1–6 个系列，名称互不重复；每组 values 与 categories 长度严格相等。只接受有限数字或 null，每系列至少一个有效值；不接受数字字符串、布尔值、NaN、Infinity。
- 必须提供 `unit`（最多 40 字符；无量纲写“比值”等），并提供 `source` 或 `citations`。百分比明确 0–1 比例还是 0–100 百分数；不自动猜测转换。
- 一个图内所有系列必须使用同一单位与可比较口径。折线 x 轴是等宽类别轴，适合等间隔随访；非等间距真实时间需要先正确分箱并保留缺测，或改表格说明。
- 图表自带内联 SVG 的 title/desc、可区分颜色/线型、图例和始终可见的数据表。下方数据表保留实际输入数值，不通过图形反推数据。
- 手机图表局部横向滚动并显示提示；打印时图、图例、图注一起保留，数据表可独立跨页。长图例或标签应主动简化解释，而非缩成不可读小字。

## 文献、编号与来源

```json
{
  "references": [
    {
      "id": "evidence-1",
      "title": "实际核实的文献标题",
      "authors": ["实际作者"],
      "year": 2025,
      "source": "期刊或发布机构"
    }
  ],
  "blocks": [
    {"type": "paragraph", "text": "由此文献支持的具体结论。", "citations": ["evidence-1"]}
  ]
}
```

`id`、`title` 必填；`authors` 接受字符串/字符串数组，`year` 接受文本或整数。外部文献应补实际核实的 `doi`/`url`，不能照抄示例标题或编造 DOI。DOI 支持裸 DOI 或 https://doi.org/ 前缀；URL 只支持 http/https。

按 references 首次定义顺序编号，重复 DOI 或 URL 合并为一条，所有别名 id 指向相同编号；缺失字段可由同一条文献的后续定义补齐。相同 id 定义冲突、DOI/URL 指向不同条目的冲突、未知 citation id 会停止生成。文末列出全部已定义条目；不要把未读、未引用的装饰性书目塞入 references。

段落、图注和表注使用相同编号体系。正文的 `[@id]` 或 `[@id-1; @id-2]` 与 block.citations 等效；文献编号由生成器决定，不手工硬编码 `[1]`。`source` 用于原始检查材料、数据来源说明、图片归属、加工方式和局限，不能替代需要提供的科学证据。

## Markdown 兼容

支持标题、段落、列表、引用、代码块、水平线、带分隔行的管线表格、`![图注](本地图片路径)`、行内图片、加粗/斜体/行内代码、http/https 或 #锚点链接。普通单独管线行按段落处理。原始 HTML 作为文本转义，不执行。

Markdown 的 `[@id]` 使用 `--references` 引入本地 JSON，内容可为文献数组或 `{"references": [...]}`。本地图片路径按 Markdown 所在目录解析；独占一行的图片显示 figure 和图注，`![图注](image.png) [@id]` 将引用放在图注内。

此解析器不是完整 CommonMark。复杂嵌套列表、引用式链接、数学公式、Mermaid 和脚注扩展不会自动变成图表；需要先转为真实图片/数据，或改用 JSON blocks。代码块内部的图片/引用语法保持原样。

## 排版检查重点

页面默认最大外框宽度 1064px、正文 16px；窄屏自动单列，图片 contain，表格只在自身容器滚动。表格使用精简横线，完整数值列自动右对齐并保留输入精度；说明类混合列维持左对齐。图例与折线使用对应的线型及圆点，深浅色和打印分别提供清晰的坐标、网格与系列配色。

打印使用 A4、16mm 边距，表头跨页重复，长表不整体锁在一页。图与图注保持同页；单图最高 165mm，原双列中的图片最高 95mm，以兼顾同页的解释文字。密集检查图宜放到全宽 image block 或提供清晰局部图；含很长图注时将详细解释移到正文，必要时拆成多个局部图，不能为容纳图注把关键字段缩到不可读。更多编排取舍见 [style-guide.md](style-guide.md)。

必须检查实际浏览器与打印预览：特别关注长中文标签、超宽表格、长 DOI/URL、竖图、缺测点、负值柱图、图注跨页和末行裁切。结构校验不能证明图片中小字号或临床细节清晰可读。
