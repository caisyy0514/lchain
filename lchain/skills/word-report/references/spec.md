# Word 报告 spec

`blocks` 可仅由标题、段落和列表组成；`image`、`chart`、`table`、`columns` 都是按需选项。以下混排示例说明可用结构，不代表每页或每章的视觉内容配额。

## 通用字段

```json
{
  "title": "报告标题",
  "subtitle": "副标题",
  "author": "机构或作者",
  "meta": {"检查日期": "实际检查日期"},
  "references": [
    {"id": "guideline", "title": "经核验的文献题名", "authors": ["实际作者"], "year": 2025, "source": "期刊或发布机构", "doi": "", "url": ""}
  ],
  "blocks": [
    {"type": "heading", "level": 1, "text": "主要发现"},
    {"type": "paragraph", "text": "论断与适用范围。", "citations": ["guideline"]}
  ]
}
```

示例中的来源和数值仅用于解释字段，实际生成必须替换成经过核验的内容。不要照抄占位题名/作者作为医学文献。

`references` 的 `id`、`title` 必填；尽可能补齐 `authors`（字符串或数组）、`year`、`source`、`doi`/`url`，可选 `volume`、`pages`。没有的字段留空，不猜测。DOI 可写裸 DOI 或 `https://doi.org/...`，URL 仅接受 http(s)。同 id 冲突报错；同 DOI/URL 的不同 id 去重，保留首条并补齐其空字段。编号按去重后的顶层定义順序稳定生成。自定义文献标题用 `references_title`。

正文、标题、列表、图像、图表、表格、引用和代码块可使用 `citations: ["guideline"]`；图、表还支持 `caption`、`source`、`sample`。`columns` 的引用放在子块中，`page_break` 不承载引文。这些标号为静态文本，手工删改文献后应从 spec 重新生成来更新编号。

## 文字与图片

既有 `heading`（level 1–3，4–6 降到 3）、`paragraph`、`bullets`、`numbered`、`quote`、`code`、`page_break` 继续支持。段落、列表和单元格支持 `**加粗**`、`*斜体*`、行内反引号和换行。

```json
{
  "type": "image",
  "path": "/repo/attachments/images/实际原图.png",
  "width_in": 5.5,
  "height_in": 4.5,
  "alt": "描述图中关键内容，不能只写图片二字",
  "caption": "图 1 检查原图及关键发现",
  "source": "实际检查机构、日期、报告或附件路径",
  "citations": []
}
```

`path` 支持绝对路径，或相对 spec 所在目录的路径；支持 PNG/JPEG/GIF/BMP，其他格式先转换。宽高单位英寸，均为上限而非强制拉伸；最终不超过当前栏/页面内容区，并预留图注空间。原图二进制嵌入，默认不放大小图。相同文件复用媒体，每处 drawing id 唯一；`alt` 写入 Office 替代文本。

图片不存在、后缀/内容不匹配、常见截断或损坏会报错。标准库检查容器与尺寸、PNG CRC/像素流；已有 Pillow 时进一步完整解码。没有解码器时 JPEG/GIF/BMP 不能保证识别全部深层损坏，仍须打开成品检查。

### 患者截图取用与示例

有助解释的患者截图/图片应取自本次提交附件；必要时把 PDF 相关页提取为清晰图片，不能只保留 OCR 文字或文件链接。先确认 `path` 对应可打开的本地文件；`source` 记录实际附件名、页码和报告日期，没有页码或日期时省略或注明未提供，不猜测。

手机照片若带 EXIF 方向信息，先按其方向导出展示副本；Word 生成器不会自动归一化 EXIF 方向。方向修正、格式转换及局部截取都在派生副本上完成，原附件保留。局部图的 `caption`/`source` 写清对应原图编号和区域；保留相关行名、数值、单位与必要上下文，不重绘、替换或遮盖临床信息。患者资料归属写在 `source`；科学解释所需的 `citations`/`references` 单独核验，不能把患者截图当成公开文献。

以下是可改写结构，文件名、页码、区域描述及路径均为示例；须替换为本次实际素材，只有确认原件未给日期时才写“未提供”。示例展示全宽原图与局部图，并非每份报告都需要两张图：

```json
{
  "title": "检查资料解读",
  "blocks": [
    {"type": "paragraph", "text": "结合图 1 的原始上下文说明本次检查，需核对的区域见图 2。"},
    {
      "type": "image",
      "path": "/repo/threads/当前会话/patient-images/检验报告_page-2.png",
      "width_in": 6.2,
      "height_in": 6.5,
      "alt": "检验报告第 2 页的整页图，保留检查标题和结果区域",
      "caption": "图 1 检验报告第 2 页：原图上下文",
      "source": "患者本次提交：检验报告.pdf，第 2 页；检查日期未提供；整页提取",
      "citations": []
    },
    {
      "type": "image",
      "path": "/repo/threads/当前会话/patient-images/检验报告_page-2_detail.png",
      "width_in": 6.2,
      "height_in": 3.5,
      "alt": "图 1 中部结果区域的局部图，保留项目名称、数值及单位",
      "caption": "图 2 图 1 中部结果区域：局部放大",
      "source": "派生自检验报告.pdf 第 2 页；局部截取，原图见图 1",
      "citations": []
    }
  ]
}
```

详细截图优先使用顶层全宽 `image`；需要独立页时在其前方添加 `page_break`，短而清晰的图片才适合 `columns`。图、图注和来源同页，较长解释另放 `paragraph` 自然分页。多图编号与正文顺序保持一致；最终渲染后逐图读清标题、关键数值及单位，再核对原图与局部图的对应位置。仍看不清时重新提取更清晰的素材或拆分局部，不能靠拉伸或只保证图片不溢出来交付。

## 图文、图表混排

```json
{
  "type": "columns",
  "ratio": [1, 1],
  "left": [
    {"type": "paragraph", "text": "左侧解释关键发现，避免塞入整章正文。", "citations": ["guideline"]}
  ],
  "right": [
    {"type": "image", "path": "/repo/attachments/images/实际原图.png", "alt": "发现示意", "caption": "图 2 局部图", "source": "原始检查单及日期"}
  ]
}
```

`ratio` 为两个有限正数；两侧数组可组合正文、图片、图表、表格。栏间保留空隙，每个子块重新计算可用宽度。长段落允许跨页，不能把整段混排锁成不可拆分的大行。单图与其说明保持一起；超长文字优先移回全宽段落。`columns` 自身不能放引用/图注，应放在对应子块中；栏内不能放 `page_break` 或嵌套 `columns`。

## 原生可编辑图表

下面是**合成排版测试数据，不是诊疗证据**：

```json
{
  "type": "chart",
  "chart_type": "line",
  "categories": ["时间一", "时间二", "时间三", "时间四"],
  "series": [
    {"name": "测试系列甲", "values": [8, 7, null, 5]},
    {"name": "测试系列乙", "values": [8, 8, 7, 6]}
  ],
  "unit": "测试单位",
  "caption": "图 3 合成排版测试图",
  "source": "合成测试数值，不可用于诊疗",
  "sample": "测试场景，无真实受试者",
  "alt": "测试折线在第三个缺测位置断开"
}
```

- 支持 `bar`（分组柱形图）/`line`，默认 bar。类别 1–12 个且不重复；line 至少 2 个；系列 1–4 个且 name 不重复。双栏内最多 6 类/2 系列，更多数据用全宽图或拆图。
- `values` 长度必须等于类别数，数字为有限值且绝对值不超过 `1e12`，极值应合理换单位。每系列至少有一个有效点。`null` 代表缺测，图中保留断点/空位，内嵌数据表相应单元格留空。
- `unit` 和 `source`/`citations` 必填。无量纲也应明确写明；患者测量需写报告日期和来源，研究对比写人群/样本量/分母、统计口径和文献。比例/百分数必须注明存的是 0–1 还是 0–100。
- 折线使用等距类别轴，不是连续日期轴。不等间隔随访应按统一时间间隔补齐缺测类别，或嵌入带真实时间轴的科学图；不能把等距位置解读为等时长或据此推断变化速度。
- 类别标签最多 24 字，系列名最多 40 字。若渲染后图例或长标签拥挤，缩短标签并在图注解释；不要用缩成不可读字号解决。
- 使用二维平面、有限系列、白底和细浅灰网格；柱形轴包含 0。默认青绿/蓝/赭黄/紫色，折线同时用不同点形与虚实线区分系列，便于灰度打印。坐标字号 10 pt、图例 9.5 pt，图例置底，不叠在数据上。相同系列跨图须维持相同顺序，才能保持颜色和点形含义一致。
- 图表、系列名称、数值缓存与可编辑 XLSX 都写入 `.docx`，不引用外部网络工作簿。二维图可手工编辑；不要加渐变、阴影、平滑曲线或没有科学意义的装饰。
- `title` 在没有 `caption` 时作为图注；推荐明确 `caption` 编号。可用 `width_in`、`height_in` 缩小图，但必须复核标签可读性。

## 表格与分页

```json
{
  "type": "table",
  "caption": "表 1 检查结果与解释",
  "headers": ["项目", "结果", "解释"],
  "rows": [["项目一", "原始数值及单位", "根据原始数据与证据填写解释"]],
  "column_widths": [2, 2, 5],
  "align": ["left", "center", "left"],
  "source": "实际报告与日期",
  "citations": ["guideline"]
}
```

`column_widths` 是相对权重，数量应与列数一致；不填时按表头与典型内容长度分配，解释列优先留宽，避免单个长值挤占整张表。`align` 每列 `left`/`center`/`right`；不填时纯数字或带常见英文单位的数值列右对齐，其余左对齐。特殊单位、日期、范围和分组表请显式指定对齐。保持同列精度和单位一致，不增加原始数据没有的有效位数。

默认学术三线表：白底、深蓝加粗表头、顶线/表头下线/底线，无竖向网格和交替底色；正文 10.5 pt，单元格留有内边距。短行缺失单元格补空，数字 0 保留，已有较宽行仍保留，不丢弃数据。内容自动换行，没有固定行高，不隐藏长文字。

表头会跨页重复，普通数据行不拆页，但整张表允许跨页。脚本估算单行大于页高时拒绝，请拆分为多行或把长说明放正文。宽表应减少列数、调整列宽或全宽呈现；不要把多列表格硬塞进半栏。禁止把几十行表整体设置 keepNext，这会形成空白页或溢出。

## 学术样式与素材约束

默认 A4 白底，墨色正文 11 pt、1.25 倍行距；主标题 24 pt，三级标题为 16/13.5/11.5 pt 的深蓝层级。通过字号、粗细和留白区分层级，不增加彩色标题栏或边框卡片。图注 10 pt，图/表编号加粗；来源、样本与缺测说明 9 pt 灰色，独立成行；引文编号以上标紧随论断，文末文献 9.5 pt、悬挂缩进，DOI 使用短标签且保持可点击。

自制插图与科学图优先白底、深蓝文字、青绿强调，辅助色用于有意义的分组；单个图使用有限字体和线宽。嵌入图片按其实际呈现尺寸制作，图内文字通常不小于 9 pt；必须缩小才能放入时改用全宽或拆成多图。原始检查截图保持原样；不能为了统一配色改变检查信息或测量结果。每页保留阅读留白，图注说明结论与限制，不在图内和正文重复整段解释。
